# Mocks

[Up: design notes](../../../DESIGN.md) · [Mock-first playbook](../../orchestration/playbooks/mock-first.md)

Local HTML mocks drawn before a UI change is built, one folder per mock. They are made with the
[mock-build](../../../.agents/skills/mock-build/SKILL.md) skill and reviewed with
[mock-review](../../../.agents/skills/mock-review/SKILL.md). Nothing here is product code.

## Layout

```
tokens.config.json   which theme file and selectors the tokens come from
tokens.css           generated by `bun run mocks:tokens`; never edited by hand
<slug>/
  mock.json          title, status, versions and the approved version
  brief.md           the problem, who meets it, what the mock must show
  decisions.md       one line per review round
  handoff.md         written on approval: the target, kit parts to real components, gaps
  kit/               tokens.css, kit.css and kit.js as they were when the mock was made
  shots/             screenshots per direction and theme for the review cards; not committed
  v1.html  v2.html   one page per version; a reviewed version is never edited
```

Screenshots are working files: `show_mock` and question cards read them from the worktree, and
`.gitignore` keeps them out of commits. Put before and after pictures in the pull request body.
A committed image must be embedded in a Markdown file; `bun run check:scaffold` fails otherwise.

[needs-you-home](needs-you-home/handoff.md) is the example mock. Its screenshots are embedded in
its handoff because the mock-presentation tests use the folder as their fixture.

Open a version in Gram with `show_panel` preview (an agent does this for you), or in any browser.
Under `file://` the bar can't read `mock.json`, so it shows no version links; serve the folder
(`python3 -m http.server`) to get them.

## mock.json

```json
{
  "title": "Needs you home",
  "slug": "needs-you-home",
  "status": "approved",
  "template": "options",
  "current": 1,
  "approved": 1,
  "versions": [{ "n": 1, "file": "v1.html", "created": "[date]" }],
  "directions": [
    {
      "name": "C Hybrid",
      "board": "c-hybrid-popover",
      "shots": {
        "dark": "shots/c-popover-dark.png",
        "light": "shots/c-popover-light.png"
      }
    }
  ]
}
```

`status` is `draft`, `in-review` or `approved`; `approved` is the approved version's number.
Keep it with `new-mock.mjs` (`--next`, `--status`, `--approve <n>`) rather than by hand.

## Tokens

`tokens.config.json` points at Gram's generated theme and names the Neutral palettes for light
and dark. After a theme change, run `bun run mocks:tokens`; the tests fail while `tokens.css` is
stale. Existing mocks keep their own `kit/tokens.css`; copy the new one in only when a mock is
being revised.
